# Alembic Migrations Setup — Cahoots (FastAPI)

Setup guide for Phase 0 → "Set up Alembic migrations".

**Context this assumes:** Python 3.14, `uv`-managed, `backend/` is the package root
(imports look like `core.config`, `database.database`, `models`), SQLModel with an
async `asyncpg` engine, Supabase Postgres, and `psycopg2-binary` already a dependency.

**Decision:** run Alembic with the **sync** psycopg2 driver even though the app runs
async. Migrations are short-lived scripts; an async `env.py` adds complexity for no
benefit here.

---

## Step 1 — Add Alembic

```powershell
cd backend
uv add alembic
```

## Step 2 — Initialize the migrations folder

```powershell
uv run alembic init migrations
```

Creates `backend/migrations/` (`env.py`, `script.py.mako`, `versions/`) and
`backend/alembic.ini`.

## Step 3 — Edit `alembic.ini`

Blank out `sqlalchemy.url` — it gets injected from settings in `env.py`, so no secret
sits in a committed file:

```ini
sqlalchemy.url =
```

Confirm this line exists near the top (lets `env.py` import the `core` / `models`
packages):

```ini
prepend_sys_path = .
```

Optional — timestamped migration filenames:

```ini
file_template = %%(year)d%%(month).2d%%(day).2d_%%(hour).2d%%(minute).2d-%%(rev)s_%%(slug)s
```

## Step 4 — Wire up `migrations/env.py`

Order matters: `config = context.config` must come **before** any use of `config`.
The top of `env.py` should read:

```python
from logging.config import fileConfig

from sqlalchemy import engine_from_config
from sqlalchemy import pool

from alembic import context

from core.config import settings
from sqlmodel import SQLModel

# Import every module that defines SQLModel tables so they register on the metadata.
# models/__init__.py is currently empty; as you add model files, import them here
# (or import the package if models/__init__.py re-exports them).
import models  # noqa: F401

# this is the Alembic Config object, which provides
# access to the values within the .ini file in use.
config = context.config

# Alembic needs a SYNC driver. settings.DATABASE_URL is postgresql://... which
# psycopg2 uses directly — good.
config.set_main_option("sqlalchemy.url", settings.DATABASE_URL)

# Interpret the config file for Python logging.
if config.config_file_name is not None:
    fileConfig(config.config_file_name)

target_metadata = SQLModel.metadata
```

In **both** `run_migrations_offline()` and `run_migrations_online()`, add
`compare_type=True` to the `context.configure(...)` call so column type changes get
detected:

```python
context.configure(
    connection=connection,
    target_metadata=target_metadata,
    compare_type=True,
)
```

## Step 5 — Patch `script.py.mako`

SQLModel autogenerate emits types like `sqlmodel.sql.sqltypes.AutoString`, so each
migration file needs the import. Add under the existing `import sqlalchemy as sa`:

```python
import sqlmodel
```

## Step 6 — Supabase connection detail

Use the **direct connection** string (host `db.<ref>.supabase.co`, port **5432**) in
`DATABASE_URL` for migrations — not the transaction pooler on port 6543. The pooler
(pgbouncer) breaks DDL and prepared statements.

If you get SSL errors, append `?sslmode=require` to the URL.

## Step 7 — Generate the first migration

```powershell
uv run alembic revision --autogenerate -m "initial schema"
```

With no models yet this will be near-empty — expected. Open the generated file in
`migrations/versions/` and review it before applying. Always review autogenerated
migrations; Alembic misses enum changes, some constraint renames, etc.

## Step 8 — Apply it

```powershell
uv run alembic upgrade head
```

Verify in Supabase → Table editor that an `alembic_version` table now exists.

---

## Day-to-day workflow

| Action | Command |
|---|---|
| Made model changes, create migration | `uv run alembic revision --autogenerate -m "add events table"` |
| Apply pending migrations | `uv run alembic upgrade head` |
| Roll back one | `uv run alembic downgrade -1` |
| Current revision | `uv run alembic current` |
| History | `uv run alembic history` |

## Cleanup notes

- **Commit `migrations/versions/*.py`** — they're source, not build artifacts. Make
  sure `.gitignore` doesn't exclude them.
- Once Alembic owns the schema, drop the `SQLModel.metadata.create_all` path in
  `backend/database/database.py` (`init_db`) so the two mechanisms don't fight.
  Schema changes go through Alembic only.
- When you add your first real model, import it in `env.py` (Step 4) or autogenerate
  won't see it.
- If you later want models auto-discovered, have `models/__init__.py` import each
  model module, then `import models` in `env.py` is enough.
